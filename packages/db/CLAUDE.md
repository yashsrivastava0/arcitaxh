# packages/db

Purpose: Drizzle schema, migrations and repository adapters (PostgreSQL) shared by the API and the future worker.

- May import: `core`. Implements ports defined in `core` / `kb` / `llm`. Never imported by `web`.
- Conventions: UUIDv7 ids generated by the app (via `IdGenerator`), `timestamptz` UTC, money as `bigint` micro-USD (no floats), snake_case plural tables, JSONB validated against Zod on write.
- Migrations are additive-then-contract. **Never edit an applied migration**; add a new one.
- `DATABASE_URL` is pooled; `DATABASE_DIRECT_URL` is direct (unused until Phase 2 streaming, declared now).
- Phase 0 tables: `kb_releases`, `kb_records`, `verdict_cache`, `debates`, `debate_turns`, `usage_events`, `phase0_*`, `waitlist_signups`. `user_id` columns are nullable with no FK (no `user` table yet); add the FK later by expand-and-contract.
- `waitlist_signups` and rater data are PII: keep the retention and deletion path documented.
- Test: integration tests need real PostgreSQL (`infra/docker-compose.yml`, or the CI service container): migrations from empty, idempotent inserts, unique constraints, `ON CONFLICT DO NOTHING` turn writes, retention queries.
